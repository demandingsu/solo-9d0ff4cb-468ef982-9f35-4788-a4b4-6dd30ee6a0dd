# 采购标段截标时间核验 + 履约地点地域初筛

面向投标专员的网页工具，提供两个入口：

1. **截标核验**：输入公告列表页地址、项目编号、标段号，沿分页抓取原公告、延期公告和终止公告，按发布时间合并出该标段当前有效的投标截止时间。
2. **地域初筛**：输入原公告目录地址和企业覆盖的完整省/市/区县，沿同站分页读取招标公告，按项目、标段提取施工或交付地点，筛出候选标段与待核标段。

应用使用 Python FastAPI，连同本地公告示例站通过 Docker Compose 启动。示例站为纯本地数据，**构建镜像后整个演示不需要访问互联网**。

## 启动

```bash
docker compose up --build
```

- 核验工具：<http://localhost:8000>
- 地域初筛：<http://localhost:8000/screen>
- 本地公告示例站：<http://localhost:8001/notices?page=1>
- OpenAPI：<http://localhost:8000/docs>

首次启动会下载 Python 镜像与依赖；镜像构建完成后，核验、初筛、翻页、查看来源链接都在本机完成，可断网演示。

停止：

```bash
docker compose down
```

## 演示用例：截标核验

首页已提供一键示例：

| 用例 | 项目编号 | 标段 | 预期 |
| --- | --- | --- | --- |
| 投标进行中（已延期） | `DEMO-2026-001` | `02` | 有效截止时间 `2026-11-12 09:30`，来源为第 4 页延期公告 |
| 已终止 | `DEMO-2026-001` | `01` | 状态“已终止”，**不显示有效截止时间**；时间线保留原公告、延期、终止三次变化及各自来源 |
| 不同编号格式 | `DEMO-2026-002` | `A` | 有效截止时间 `2026-11-25 14:00`；A 包的成交结果公告不改变截止时间 |

示例数据故意分布在第 1–5 页：`DEMO-2026-001` 的原公告在第 1 页，01 标段延期在第 3 页，终止在第 5 页；同项目 02 标段也有自己的公告，核对 01 标段时不会被混入。

## 截标核验规则

1. **分页发现**：从列表页开始，沿 `rel=next`、分页器内的页码/下一页链接继续抓取，直到没有更多页或达到安全上限。
2. **精确匹配标段**：只有详情页中项目编号和目标标段号同时匹配才纳入合并。列表页有明确项目/标段信息时会先排除其他项目和其他标段，详情页仍会再次校验，避免混入同项目其他标段。
3. **按发布时间排序**：将命中的原公告、延期/更正公告、终止公告按详情页发布时间合并。
4. **只应用明确修改**：延期公告只有载明新的投标截止时间时才替换旧时间；页面只是引用旧时间、或只说“另行通知”而没有新时间时，结论为“无法判定”，不会把旧时间继续当作有效时间。
   - 同时支持“原时间……现延期至……”“……变更为……”“变更后：……”等写法，避免把“原时间”误当新时间，也不会把开标时间误当投标截止时间。
5. **终止优先**：一旦终止公告发布，状态固定为“已终止（不再接受投标）”，有效截止时间为空，旧时间只出现在历史时间线中并明确标注失效。
6. **失败即无法判定**：列表页、分页页、候选详情页抓取失败，详情页关键字段无法解析，缺少原公告，或相关公告缺少发布时间导致无法排序时，页面显示“无法判定”和失败/检索地址，并置空有效截止时间。**不会沿用之前的查询结果**。
7. **无缓存**：每次查询都实时重新抓取，不保存、不读取旧结论。

其他公告（如成交结果公告）可以出现在命中的公告列表中，但不会改变标段状态或截止时间。

## 地域初筛规则

1. **整目录读取**：从公告目录第一页开始沿分页抓完整个目录，逐个读取详情页；只依据招标（原）公告提取地点，延期/终止/结果公告不参与地点口径（投标状态由截标核验负责）。
2. **只认履约地点标签**：仅“履约地点/施工地点/工程地点/交付（货）地点/服务地点/项目地点/建设地点/实施地点/服务（施工）区域/工程（项目）所在地”等明确标签的字段算数。**代理机构地址、采购人地址、开标地点、文件递交/提交地点一律不算项目地点**。
3. **专属优先，共用补空**：标段条目内的专属地点优先；公告级共用地点只补给没有专属地点的标段。
4. **全部落在覆盖内才算候选**：同一标段有多个履约地点时，必须每一个都归属覆盖区县才列为候选；任何一个在覆盖外即整个标段落入范围外。
5. **归属不清列待核**：地点缺少上级区划（只写区县、没写所属地市）或无法识别区县归属时，该标段列入待核并展示地点原文，**不猜测归属**；公告未载明履约地点的标段同样列待核。
6. **覆盖名单要完整**：覆盖条目须为“省+市+区县”（直辖市视同市级）；缺少上级区划或无法识别的条目不生效，并在页面上明确提示。
7. **失败即整轮不完整**：任一目录页或详情页读取失败，整轮标记为不完整——页面仍列出已发现的候选/待核，但明确提示结果可能不全，**不能据此声称没有候选**。

初筛结果中每个候选/待核标段都展示地点原文（含专属/共用来源）、来源公告链接和“截标核对”入口，供专员继续确认投标状态。

## JSON API

截标核验：

```bash
curl -G http://localhost:8000/api/check \
  --data-urlencode 'list_url=http://localhost:8001/notices?page=1' \
  --data-urlencode 'project_no=DEMO-2026-001' \
  --data-urlencode 'section_no=01'
```

也支持 `POST /api/check`（JSON body 同参数）。关键返回字段：`status`（`ongoing` / `extended` / `terminated` / `unknown`）、`determinable`、`effective_deadline`、`deadline_source_url`、`changes`、`failures`、`notices`。

地域初筛：

```bash
curl -G http://localhost:8000/api/screen \
  --data-urlencode 'list_url=http://localhost:8001/notices?page=1' \
  --data-urlencode 'coverage=云洲省云州市滨河区
云洲省云州市西岭县'
```

也支持 `POST /api/screen`：

```json
{
  "list_url": "http://localhost:8001/notices?page=1",
  "coverage": "云洲省云州市滨河区\n云洲省云州市西岭县"
}
```

关键返回字段：

- `complete`：整轮抓取是否完整；为 `false` 时候选/待核列表可能不全
- `candidates` / `review` / `outside`：候选、待核、范围外标段；每条含 `places`（地点原文、专属/共用、归属判定）、`sources`（来源公告）、`check_url`（截标核对入口）
- `coverage` / `coverage_warnings`：生效的覆盖区县与被剔除的条目说明
- `failures`：抓取/解析失败地址及原因
- `searched_pages`、`detail_page_count`、`notice_count`：抓取范围统计

## 本地测试

不启动容器也可运行解析与合并规则测试（需要先安装 `requirements.txt`）：


## 边界与限制

- 只抓取 HTTP/HTTPS 的 HTML 页面；链接限定在输入列表页同一站点（scheme + host），不会跟随站外跳转。
- 单次查询设置列表页/详情页数量和响应大小上限，避免误抓大型站点；超过上限时结论为“无法判定”（截标核验）或“整轮不完整”（地域初筛），而不是猜测。
- 不处理需要登录、验证码、JavaScript 动态渲染的公告站。
- 日期按页面原始时区文本解析（示例为北京时间），不进行时区换算。
- 地域初筛按公告原文做行政区划文本匹配，不内置全国区划数据库；地点写法不规范时一律列待核，由人工确认。
- 示例站数据（含云洲省、云州市等区划）均为虚构，不代表任何真实采购项目。
